## Task 3
- Awarded: 1b   (max 1b)
- Commentary: Complete and well argued. The student proposes soft Precision/Recall/F1 (adapted from the Soft Execution F1 paper, with the citation) plus Jaccard, gives explicit per-question formulas, defends applicability to retrieval-style Text2SQL results, and explicitly addresses the complement-vs-replace question (F1 gives partial credit where exact execution accuracy is binary; it does not replace it because high F1 can hide missing/extra rows, and it tests one database instance rather than SQL-logic equivalence). Edge-case conventions (both-empty = 1, SQL errors = 0, duplicate-count blind spot) are documented, LLM-as-a-judge is considered and justifiably rejected. The implementation (evaluate_soft_execution.py, soft_scores, plus Jaccard in generate_dashboard.py) was run on the Task 2 predictions, and report.html shows the per-prompt comparison (CRISP P 63.9% / R 49.5% / F1 50.8% / J 49.5% vs RACE ~33% and ToT ~30%), with a matching interpretive README noting all metrics preserve the same ranking.

## Task 4
- Awarded: 1.5b   (max 2b)
- Commentary: The interactive dashboard (report.html) delivers excellent tables and graphs: a scorecard with Accuracy/Precision/Recall/F1/Jaccard/mean latency, per-question latency line plots with correctness colouring, an accuracy-vs-latency scatter, stacked breakdowns by gold-result size and by question-length bucket, pairwise disagreement bars (e.g. CRISP-only 41 vs RACE-only 7), and a filterable case browser — a genuinely detailed analysis of the metric values per prompt, going well beyond Task 3.
