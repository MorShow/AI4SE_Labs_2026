# Report

For this task, I decided to build a fairly simple agent network consisting of four LLM nodes:

1. Extractor collects requirements from each document, processing the documents one at a time.
2. Consolidator combines the extracted requirements into a single document.
3. Reviewer identifies inconsistencies, duplicates, and other problems in the report generated by the second node.
4. Architect reassesses the priorities of the reviewed requirements from a developer's perspective.

## Review and Feedback Loop

The Reviewer generates a review and classifies the second node's errors into three severity levels: Critical, Medium, and Low.I've decided that the report is rejected if the review identifies at least one Critical error, or at least three Medium errors.
When either condition is met, the feedback loop is triggered, and the second node must regenerate the consolidated report. I chose these thresholds to give the second node a chance to pass even with a report that is not perfect :).

This review validates the input passed to the fourth node.

## Developer-Oriented Prioritization

The fourth node reprioritizes requirements based on their importance to developers rather than to the business.

For example, if a database schema redesign is a prerequisite for all subsequent changes, it should be done first and receive High priority from this model, even if the task is less attractive from a business perspective.

Unfortunately, I did not validate the prompt thoroughly enough before running the system. As a result, I am not entirely satisfied with the definitions of High, Medium, and Low priority. The fourth model very often agreed with the report passed on by the third node, so I did not obtain many significant changes.

## Generated Report

At the end, the system assembles a formatted Markdown report. Examples are `final-requirements.md` and `final-requirements2.md`, which contain slightly different reports.

The report lists requirements of four types:

- Functional
- Non-functional
- Interface
- Additional, such as legal requirements

It includes links to source documents and related requirements, as well as a blacklist of requirements that did not pass the review.

The generated [README.md](./README.md) explains how to run the system.
